## Where things stand

`main` is at `1cddb7d`, PR #21 squashed in (round 1, no defects). CI green on
both jobs (push event and pull_request event), re-confirmed independently by
Sam at the release gate rather than taken on report: `bun run test` 416 passed

**The format is now published.** `/schema` lists every field of a design with
its type, whether it is required, and what it means; the two cross-field rules
the schema file cannot express — unique node ids, and edges naming defined
nodes — are carried in prose beside it, together with D20's two-pass reality;
`public/sample.json` is shown in a code block with a labelled copy button and
a download link; `public/design.schema.json` is generated by Zod's own
`z.toJSONSchema(designSchema, { io: 'input' })` (no new dependency), rewritten
by `bun run schema`, and pinned against drift by a test that regenerates and
compares. Both `/schema` and `/` now share `src/layouts/PageLayout.astro` and
`src/styles/page.module.css` — the page-styling decision parked since
Task 03. The upload page has a "Load the sample design" button that fetches
`/sample.json` and runs it through the same `loadDesign` path as any uploaded
file.

Two user decisions this cycle are now published behaviour, not just
implementation detail: (1) the schema is generated with `io: 'input'`, so it
omits `additionalProperties` and accepts exactly what the app accepts —
verified against ajv across a 13-case corpus, agreeing with `loadDesign` on
every case but the two cross-field rules; (2) both cross-field rules stay in
prose only and the generated artifact is never hand-edited. D90–D97 record
both, append-only, in `docs/DECISIONS.md`.

**Not live anywhere yet** — Task 10 is what deploys to Netlify.
